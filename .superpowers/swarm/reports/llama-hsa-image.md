# Llama HSA Image Generator

`experiments/native-r9700-runtime/generate_hsa_code_image.py` is a generation-time-only direct-COMGR producer for the fresh `llama_embed_row_f16.cpp` source. It imports no product runtime and makes no device, allocation, queue, or dispatch call.

The producer admits only ELF64 little-endian `ET_DYN` AMDGPU objects. It range-checks every ELF section and only maps the V1 allocated-section allowlist. The output image is a page-address layout: every admitted allocated payload is copied at `sh_addr - min(sh_addr)`. Direct COMGR's `.relro_padding` NOBITS section and its exact one-byte allocated `.bss` sentinel are zero-filled in their image ranges; every other allocated NOBITS section, TLS section, unadmitted allocated section, malformed table, unaligned section, overlap, and out-of-range arithmetic is rejected.

It reads all symbol tables, collects every `llama_embed_row_f16` record, and requires their unique `(section_index, value)` target set to contain exactly one `.text` entry; equivalent `dynsym` and `symtab` records are admitted. The manifest preserves the matching record count and its distinct-target count separately. The only admitted `.bss` records are compiler markers (including duplicates) named exactly `__hip_cuid_<lowercase-hex>`, whose section is the exact one-byte sentinel, whose value equals its address, and whose size is at most one byte; every other `.bss` symbol is rejected. It rejects every relocation to or from the `.bss` sentinel. It resolves only AMDGPU `REL64` relocations whose `sh_info` target and defined symbols remain in admitted allocated sections, applying `S + A - P` before descriptor validation.

The `.rodata` payload must be one 64-byte AMDHSA descriptor. Its 24-byte kernarg ABI, zero group/private/preload fields, `0x408` code properties, positive resources, and signed entry delta are all cross-checked against the copied image and kernel symbol.

Publication securely opens the output parent, creates one private staging directory as its direct child, and writes plus fsyncs both `<kernel>.image` and `<kernel>.json` there. It publishes that directory exactly once through Darwin libc `renameatx_np` with `RENAME_EXCL`, so an existing or racing final name is never overwritten and no partial final directory is exposed. After publication it reopens and fstats the final directory through the parent dirfd before fsyncing the parent. The manifest binds image digest/size, offsets, descriptor resources, section layout (including the `.bss` sentinel when emitted), and ELF admission counts.
