# F1 Multi-PDB1 Resident Mapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the existing C0-derived dynamic page-table owner so the R9700 persistent service can map the complete resident Llama model across multiple 1 GiB PDB1 regions, then pass the real F1 process smoke.

**Architecture:** Keep the borrowed C0 root and PDB1 pages. The base PDB1 slot continues to borrow the fixed PDB0/PTB0 pages; later PDB1 slots allocate owned PDB0 pages, and every non-base 2 MiB region allocates an owned PTB. Ownership is explicit and hierarchical: leaf mappings count against PTBs, PTBs count against PDB0 pages, and unmap/rollback unlinks and releases children before parents. Large-BAR virtual capacity is the allocator-visible VRAM interval, bounded to the current PDB2 entry; small-BAR behavior remains aperture-bounded.

**Tech Stack:** C++17, pytest C++ compile probes, TinyGPU/AMDev page-table backend, direct `xcrun clang++`, real R9700 smoke through `native_r9700.native_worker`.

## Global Constraints

- Work only in `<repo-root>` on `feature/r9700-products-wave-a`.
- Preserve C0 fixed root/PDB1/PDB0/PTB0 ownership; never clear, free, or reallocate borrowed pages.
- Reuse existing PTE encodings: parent `physical_page | kPteValid`; leaf `physical_page | kPteLeafVramCached`.
- All parent/leaf writes require readback; all mapping changes flush GC and MMHUB using the existing ordering contract.
- No guessed register offsets or bitfields. Page-table index shifts remain `PDB2=39`, `PDB1=30`, `PDB0=21`, `PTB=12` with current masks.
- One PDB2 entry covers `1 << 39` bytes. Reject ranges that leave the fixed C0 PDB2 entry.
- Large-BAR resident limit is `resident_gpu_va_base + allocatable_bytes`, capped at the end of the current PDB2 entry; small-BAR limit remains `resident_gpu_va_base + BAR-visible allocatable_bytes`.
- TDD: one focused RED/GREEN command per task. Run the relevant subsystem suite once after Task 3; run the real hardware smoke once after the build.
- No broad repository regression or repeated review between edits. One acceptance review after the real smoke.

- [ ] **Step 3: Implement hierarchical keys and ownership**

Add:

```cpp
struct PageTableKey {
  uint16_t pdb1_index;
  uint16_t pdb0_index;
  bool operator<(const PageTableKey& other) const;
};

struct DynamicPdb0 {
  VramAllocation allocation;
  uint16_t pdb1_index;
  uint32_t linked_ptb_count;

```

Extend `Leaf` with both indices. Borrow `fixed_pages_.pdb0_page` only for the base PDB1 index; borrow `fixed_pages_.ptb0_page` only for the base `(pdb1,pdb0)` pair. Allocate/zero/link other PDB0 pages through `fixed_pages_.pdb1_page`; allocate/zero/link PTBs through the selected PDB0 page. Validate all leaves and ownership before mutation. Clear/readback leaves, then empty PTB parents, flush, release PTBs, then clear/readback empty dynamic PDB0 parents, flush, and release PDB0 pages. Preserve ownership records on any write/readback/flush/release failure for same-range retry.
