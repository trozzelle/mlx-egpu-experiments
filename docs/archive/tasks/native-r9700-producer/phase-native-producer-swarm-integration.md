## Goal

Execute the Llama and Qwen delivery packets through repeated, focused agent waves without concurrent hardware access, duplicated shared contracts, archive dependencies, or proof/test sprawl.

## Dependencies

- Shared work boundary stays the current linked worktree on branch `feature/native-r9700-producer`.
- C0 direct proof, resident VRAM smoke, and real Llama embedding-row smoke are current hardware baseline gates.
- Every source worker receives the global constraints from the master plan.

## Orchestration map

- **Sequential blockers:** shared ABI → Wave 1 source assets → serial asset integration → model stage executor → full producer → model-specific parity.
- **Parallelizable task sets:** every disjoint source file/task set in the same wave. Llama and Qwen source lanes may run together; hardware may not.
- **Shared contracts/artifacts:** kernel stage names, generated HSA manifests, `KernelAssetIntegrator`, current worktree, lower-BAR window limits, log vocabulary, model-specific cache artifacts.
- **Coordination risks:** `hsa_code_image_asset.*`, `kernel_catalog.*`, `amdev_session.cpp`, `runner.cpp`, and generated manifests have one owner per wave. Llama/Qwen workers must message the owner and block on an ABI conflict rather than edit those files.

## Handoff notes

**Speed discipline:** the supervisor must repeatedly prefer the next model-forward deliverable over new abstractions, benchmark work, broad test additions, extra primitive experiments, documentation redesign, or side-quest reviews. A task that does not directly unlock an HSA stage, complete native artifact, or exact parity gate is deferred.
