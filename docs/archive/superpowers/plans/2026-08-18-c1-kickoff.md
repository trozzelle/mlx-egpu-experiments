## Wave 1 Lane A: native runner runtime shell (task set 4)

### Target

- New production root `native_r9700/` and tests `tests/native_r9700/` (README and ROUTAGE permitting; keep files small and focused).
- Refactor the proven C0 probe's runtime lifecycle from `experiments/native-r9700-runtime/native_amdev_transfer_probe.cpp` into a **reusable runtime shell** for C1: TinyGPU init, VM/sysmem mapping, SDMA copy, kernel-blob load, kernarg write, compute dispatch, timeline poll, readback, cleanup — with standardized log writing.
- `validation-commands.md` gains the runtime-shell build/run/log command.

### Change

1. Create a new native runtime header/source under `native_r9700/` (e.g. `native_r9700/runtime.h` + `.cpp`) that exposes a narrow harness-callable lifecycle, reusing the proven sequence from the C0 probe (construct from `run_kernel_proof_scaffold`, `submit_sdma_copy`, `submit_compute_dispatch`, `poll_compute_timeline`, `finish_kernel`, `print_kernel_log`):
   - init (TinyGPU server connect, BAR mapping, arch discovery);
   - allocate VM/sysmem buffers (staging, readback, sdma-control, compute-control);
   - copy (host->device staging via SDMA);
   - kernel load + kernarg write (24-byte layout);
   - dispatch + timeline poll;
   - readback + CPU comparison;
   - logged cleanup.
2. Standardize the run-log contract: timestamped path under `logs/`, command line, substrate, device identity, build metadata, input/output digest, exit status, failure text. Reuse the C0 `print_*_log` field conventions.
3. Do NOT modify `experiments/native-r9700-runtime/native_amdev_transfer_probe.cpp` — the C0 probe is the proven reference and must stay byte-stable (it backs the passed `--kernel-proof`). Refactoring means extracting/adapting the sequence, not editing the committed file.
4. Keep the shell C1-shaped: no model math, no serving, no network transport.
5. Record the runtime-shell build/run/log validation command in `validation-commands.md`.

### Acceptance

- A `native_r9700` runtime shell exists that can initialize the macOS substrate and run the C0 minimal kernel-launch sequence (or a documented, reviewed narrow unit that exercises the lifecycle without hardware when hardware is unavailable).
- Every invocation writes a standardized local log under `logs/`.
- C0's committed probe file is untouched (verify unchanged vs HEAD).
- Downstream task sets 5-8 can call the shell without duplicating runtime init/cleanup.
- `validation-commands.md` records the runtime-shell command and the existing `tests/test_native_amdev_transfer_contract.py` regression command.
